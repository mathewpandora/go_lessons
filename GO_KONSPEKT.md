## 1. С чего начинается программа на Go

В Go программа обычно запускается из пакета `main`, а точка входа - функция `main()`.

Простейший вид:

```go
package main

import "fmt"

func main() {
	fmt.Println("test")
}
```

Что здесь важно:

- `package main` говорит, что это исполняемая программа;
- `import "fmt"` подключает пакет для вывода;
- `func main()` - главная функция, с нее начинается выполнение.

### Порядок запуска программы

По твоему коду уже видно важный порядок:

1. подключаются пакеты;
2. инициализируются глобальные переменные;
3. выполняются функции `init()`;
4. запускается `main()`.

Это важно понимать, потому что иногда код в `init()` срабатывает еще до `main()`.

Пример идеи:

```go
package main

import "fmt"

var a = func() int {
	fmt.Println("global var init")
	return 0
}()

func init() {
	fmt.Println("init")
}

func main() {
	fmt.Println("main")
}
```

Ожидаемый порядок вывода:

1. `global var init`
2. `init`
3. `main`

## 2. Переменные и константы

Это одна из самых базовых тем, и у тебя она уже хорошо покрыта.

### Объявление переменных

Можно так:

```go
var age int
```

Можно сразу со значением:

```go
var age int = 30
```

Можно дать компилятору самому вывести тип:

```go
var age = 30
```

Можно коротко, но только внутри функции:

```go
age := 30
```

### Что важно понять

- `var` можно использовать и внутри, и вне функций;
- `:=` работает только внутри функций;
- Go строго следит за типами;
- если переменная объявлена и не используется, будет ошибка компиляции;
- у переменных есть значения по умолчанию.

### Значения по умолчанию

Если переменную объявили, но не присвоили значение, у нее будет `zero value`.

Примеры:

- `int` -> `0`
- `float64` -> `0`
- `bool` -> `false`
- `string` -> `""`
- указатель -> `nil`

### Константы

Константы задаются через `const`.

```go
const Pi = 3.14
```

Группа констант:

```go
const (
	a = 1
	b = 2
	c
)
```

Здесь `c` получит значение предыдущей константы, то есть `2`.

### Что уже видно по твоему коду

Ты уже понял несколько важных вещей:

- короткая запись `:=` удобна для локального кода;
- Go не любит "мертвые" переменные;
- типизация здесь строже, чем в Python;
- значения по умолчанию надо помнить, потому что они используются часто.

## 9. Байты и руны

Это как раз одна из тем, где ты оставлял больше всего вопросов.

### `byte`

`byte` - это псевдоним для `uint8`.
Обычно его используют, когда хотят подчеркнуть: "тут именно байт данных".

### `rune`

`rune` - это псевдоним для `int32`.
Обычно его используют, когда хотят подчеркнуть: "тут символ Unicode".

### Почему `str[0]` дает число

Пример:

```go
str := "Hello"
fmt.Println(str[0])
```

Почему выводится число?

Потому что `str[0]` - это не строка и не руна, а первый байт строки.
А байт - это число.

Для `"Hello"`:

- `H` хранится как код;
- `str[0]` возвращает этот код;
- поэтому печатается число.

Если хочется увидеть именно символ:

```go
fmt.Println(string(str[0]))
```

### Почему тип `uint8`, а не `byte`

Потому что `byte` - это просто псевдоним.
Под капотом реальный тип остается `uint8`.
Поэтому `reflect.TypeOf(str[0])` показывает `uint8`.

### Почему с русскими буквами все сложнее

Потому что русская буква в UTF-8 обычно занимает больше одного байта.

Когда ты пишешь:

```go
str := "Привет"
fmt.Println(str[0])
```

ты получаешь только первый байт кодировки буквы, а не букву целиком.

### Как правильно итерироваться по символам

Вариант 1:

```go
for _, r := range str {
	fmt.Println(r, string(r))
}
```

Здесь `r` - руна, то есть уже символ Unicode.

Вариант 2:

```go
runes := []rune(str)
fmt.Println(runes[0], string(runes[0]))
```

### Ответ на твой вопрос про отрицательную `rune`

Почему отрицательное число дает странный символ?

Потому что `rune` действительно основан на `int32`, но не любое число соответствует корректному Unicode-символу.
Отрицательные значения обычно не представляют валидный Unicode-код, поэтому при печати через `%c` ты видишь "непонятный" результат.

### Очень короткое правило

- нужен сырой байт -> `byte`
- нужен символ -> `rune`
- нужен нормальный проход по Unicode-символам -> `range` по строке или `[]rune`

Это как раз тема, про которую ты писал, что ее надо разобрать подробнее.

### Что вообще происходит

Любое число в памяти хранится в битах:

```text
5  = 101
3  = 011
```

Побитовые операции работают с каждым битом отдельно.

### `&` - побитовое И

Бит будет `1`, только если в обоих местах `1`.

```text
101
011
001
```

Пример:

```go
fmt.Println(5 & 3)
```

Результат: `1`

### `|` - побитовое ИЛИ

Бит будет `1`, если хотя бы в одном месте `1`.

```text
101
011
111
```

Результат: `7`

### `^` - побитовое исключающее ИЛИ

Бит будет `1`, если биты разные.

```text
101
011
110
```

Результат: `6`

### `^a` - побитовое НЕ

Инвертирует биты.

### Сдвиги

`<<` - сдвиг влево  
`>>` - сдвиг вправо

Пример:

```go
num := 5
fmt.Println(num << 1)
fmt.Println(num >> 1)
```

### Где это реально используется

Чаще всего:

- флаги;
- права доступа;
- маски;
- сетевые протоколы;
- низкоуровневые задачи;
- оптимизации в специальных местах.

### Твой пример с правами доступа

Это очень хороший практический пример:

```go
const (
	execute = 0b001
	write   = 0b010
	read    = 0b100
)
```

Можно собирать права так:

```go
permission := execute | read
```

А проверять так:

```go
permission&execute > 0
```

Это значит:

- берем число с правами;
- проверяем, установлен ли нужный бит;
- если да, значит право есть.

### Частый простой вывод

Побитовые операции не самая базовая тема для старта, но понимать маски и проверки очень полезно.

## 19. `switch`

Ты уже использовал:

- обычный `switch` по значению;
- `switch` без выражения;
- `fallthrough`;
- `type switch`.

### Обычный `switch`

```go
switch day {

}

```

Но пользоваться этим нужно осторожно, чтобы код не стал путаным.

### `switch` без выражения

```go
switch {
case day == 1:
	fmt.Println("Понедельник")
case day == 2:
	fmt.Println("Вторник")
}
```

Это похоже на набор `if / else if`.

### Type switch

Ты уже попробовал очень важную тему:

```go
var x any = "sad"

switch v := x.(type) {
case int:
	fmt.Println("int", v)
case string:
	fmt.Println("string", v)
default:
	fmt.Println("unknown", v)
}
```

Это используется, когда значение может быть разного типа.

## 20. Область видимости

Это очень важная тема, и у тебя уже есть несколько хороших примеров.

### Главное правило

Переменная существует только в пределах своего блока.

Пример:

```go
if x > 5 {
	y := 230
	fmt.Println(y)
}
```

После выхода из блока `if` переменной `y` уже нет.

### Затенение переменной

У тебя есть пример:

```go
a := 5
if true {
	a := 10
	fmt.Println(a)
}
fmt.Println(a)
```

Результат:

- внутри блока будет `10`;
- снаружи останется `5`.

Это не изменение старой переменной, а создание новой с тем же именем внутри внутреннего блока.

Это называется shadowing, или затенение.

## 28. Замыкания

Это одна из тем, где у тебя уже хорошие комментарии.

### Что такое замыкание простым языком

Замыкание - это функция, которая "помнит" переменные из внешней области видимости.

Пример по смыслу из твоего кода:

```go
func helloFactory(lang string) (func(string), error) {
	var message string

	switch lang {
	case "ru":
		message = "Привет, %s\n"
	case "en":
		message = "Hello, %s\n"
	default:
		return nil, fmt.Errorf("такого языка нет")
	}

	return func(name string) {
		fmt.Printf(message, name)
	}, nil
}
```

### Что тут важно

Функция, которую мы возвращаем, использует переменную `message`, хотя внешняя функция уже закончилась.

Это и есть замыкание.

### Почему переменная не исчезает

Потому что возвращенная функция все еще на нее ссылается.
Пока функция нужна, нужные ей данные тоже сохраняются.

### Простая бытовая аналогия

Как будто ты создал шаблон приветствия один раз, а потом этот шаблон еще долго используешь.

## 30. Указатели и функции

Это тема, которую ты уже связал с `Scan`, и это очень правильная связь.

### По умолчанию аргументы копируются

Теперь `val` снаружи реально поменяется.

Да, ты правильно понял:

- значение можно менять через саму переменную;
- а если у тебя есть указатель, то через `*p` ты меняешь значение в той же самой ячейке памяти.

## 34. Ошибки в Go

Это одна из центральных тем языка.

### Главное правило

В Go ошибки - это обычные значения.

Очень часто функция возвращает:

```go
(result, error)
```

Пример:

```go
func divide(n1, n2 int) (int, error) {
	if n2 == 0 {
		return 0, errors.New("divide by zero")
	}
	return n1 / n2, nil
}
```

### Как читать такой код

Если ошибка есть:

- результат часто нулевой;
- `error` не `nil`.

Если ошибки нет:

- результат нормальный;
- `error == nil`.

### Проверка ошибки

```go
res, err := divide(5, 0)
if err != nil {
	fmt.Println(err)
	return
}
fmt.Println(res)
```

Это один из самых типичных шаблонов во всем Go.

## 35. `errors.New`, `fmt.Errorf`, `log.Fatalf`

Ты специально оставлял вопрос про различия между ними.

### `errors.New("...")`

Создает простую ошибку с текстом.

```go
err := errors.New("some error")
```

Используется, когда просто нужно вернуть сообщение об ошибке.

### `fmt.Errorf("...")`

Создает ошибку с форматированием.

```go
err := fmt.Errorf("user %s not found", name)
```

Это удобно, когда в текст ошибки надо подставить данные.

### `fmt.Errorf` с `%w`

Очень важная вещь:

```go
return fmt.Errorf("logicY: %w", err)
```

Так одна ошибка оборачивается в другую.
Это помогает понять путь ошибки по цепочке функций.

### `log.Fatalf("...")`

Это уже не просто создание ошибки.

`log.Fatalf`:

1. пишет сообщение в лог;
2. завершает программу.

То есть это не "ошибка как значение", а "аварийное завершение программы с логом".

### Очень короткая разница

- `errors.New` - создать простую ошибку;
- `fmt.Errorf` - создать или обернуть ошибку удобнее;
- `log.Fatalf` - напечатать и сразу закончить программу.

### Практический вывод

- внутри обычных функций лучше возвращать `error`;
- в `main()` уже можно решать, логировать ли и завершать ли программу;
- библиотечный код обычно не должен сам вызывать `log.Fatalf`.

## 36. Паника и `recover`

У тебя уже есть пример с `panic()` и `recover()`.

### Что такое паника

Паника - это аварийный сбой выполнения программы.

Пример:

```go
panic("что-то пошло не так")
```

Если ее не перехватить, программа завершится со стеком вызовов.

### Что такое `recover`

`recover()` позволяет поймать панику.
Но работает он только внутри отложенной функции, вызванной через `defer`.

Пример идеи:

```go
func handlePanic() {
	if r := recover(); r != nil {
		fmt.Println("Паника обработана:", r)
	}
}
```

### Главное отличие ошибки от паники

Ошибка:

- это ожидаемая ситуация;
- она возвращается как значение;
- ее проверяют через `if err != nil`.

Паника:

- это аварийный сценарий;
- ломает обычный ход выполнения;
- используется намного реже.

### Простое правило

Для обычных проблем:

- файл не найден;
- неправильный ввод;
- деление на ноль по логике программы;

обычно возвращают `error`.

`panic` используют, когда ситуация действительно ненормальная или при обучении, чтобы посмотреть механику.

## 37. `defer`

Это одна из самых интересных тем в твоем коде.

### Что делает `defer`

`defer` откладывает выполнение функции до момента выхода из текущей функции.

Пример:

```go
func divide1(n1, n2 int) {
	defer fmt.Println("Конец функции")
	fmt.Println(n1 / n2)
}
```

Даже если внутри произойдет паника, `defer` все равно успеет выполниться.

### Где это реально полезно

Очень часто для освобождения ресурсов:

- закрыть файл;
- закрыть соединение;
- закрыть тело HTTP-ответа;
- снять блокировку;
- сделать финальную очистку.

### Порядок выполнения `defer`

Да, ты правильно предположил в комментарии:

отложенные вызовы работают по принципу стека.

То есть:

- последний `defer` выполнится первым;
- первый `defer` выполнится последним.

Это LIFO.

### Почему в одном примере выводится `5`

Ты оставлял вопрос про это.

Когда ты пишешь:

```go
defer func() {
	fmt.Println(i)
}()
```

внутренняя функция захватывает саму переменную `i`, а не копию ее текущего значения.

Если позже `i` изменится, то при выполнении `defer` ты увидишь уже новое значение.

### Почему вариант с параметром ведет себя иначе

```go
defer func(i int) {
	fmt.Println(i)
}(i)
```

Здесь значение `i` копируется в параметр в момент регистрации `defer`.

Поэтому:

- без параметра часто печатается уже измененное значение;
- с параметром печатается значение на момент `defer`.

### `defer` и именованный результат

У тебя есть очень хороший пример:

```go
func WTF() (i int) {
	i = 5
	defer func() { i++ }()
	return i
}
```

Почему возвращается `6`?

Потому что:

1. есть именованный результат `i`;
2. `return i` подготавливает возврат;
3. перед реальным выходом выполняется `defer`;
4. `defer` меняет ту же самую переменную результата.

### А если результат не именованный

```go
func WTF2() int {
	i := 5
	defer func() { i++ }()
	return i
}
```

Тут обычно вернется `5`, потому что возвращаемое значение уже скопировано отдельно.

### Важное исключение

Если программа завершится через `os.Exit`, обычные `defer` не успеют отработать так, как при обычном выходе из функции.

## 38. Стек вызовов

У тебя уже есть пример с `debug.PrintStack()`.

### Что такое стек вызовов

Когда одна функция вызывает другую, Go хранит эту цепочку.

Например:

```text
main -> fn1 -> fn2
```

Это и есть стек вызовов.

### Почему говорят LIFO

Последняя вызванная функция завершается первой.

Если:

```text
main вызвала fn1
fn1 вызвала fn2
```

то сначала завершится `fn2`, потом `fn1`, потом `main`.

### `debug.PrintStack()`

Показывает цепочку вызовов.

Это полезно для:

- отладки;
- понимания, кто кого вызвал;
- анализа паники.

## 39. Рекурсия

У тебя уже есть:

- бесконечная рекурсия;
- рекурсия со стоп-условием;
- факториал.

### Что такое рекурсия

Это когда функция вызывает сама себя.

### Две главные части рекурсии

1. базовый случай;
2. рекурсивный шаг.

Пример:

```go
func factorial(n int) int {
	if n == 0 {
		return 1
	}
	return n * factorial(n-1)
}
```

### Что здесь происходит

- пока `n` не равно `0`, функция вызывает сама себя;
- когда `n == 0`, рекурсия останавливается;
- дальше результаты "разворачиваются назад".

### Ответ на твой комментарий про стек

Да, каждый рекурсивный вызов - это новый кадр стека.
Это не один и тот же вызов, а новая активная копия функции со своими локальными данными.

### Что будет при бесконечной рекурсии

Программа упрется в переполнение стека и упадет.

### Что такое пакет

Он помогает:

- разделять код;

### Почему пакеты полезны

Когда проект растет, код по папкам и пакетам становится намного удобнее, чем один огромный файл.

## 45. Ответы на мои вопросы из комментариев

Ниже собраны ответы именно на те места, где я в коде оставлял сомнения, вопросы или пометки "разобрать подробнее".

### Почему `main` может быть подчеркнут

Обычно такое бывает, если:

- файл не используется как основной исполняемый пакет в текущем запуске;
- в папке несколько файлов с конфликтами;
- IDE запускает другой файл;
- есть ошибка в файле или пакете.

Сам по себе `main` нормальный и правильный.

### Почему `str[0]` дает число, а не букву

Потому что это байт.
Байт - число.

### Почему `reflect.TypeOf(str[0])` показывает `uint8`, а не `byte`

Потому что `byte` - это псевдоним `uint8`.
Реальный тип в отражении показывается как `uint8`.

### Почему с русскими буквами по индексу проблема

Потому что строка хранится в байтах UTF-8, а русские буквы занимают несколько байтов.

### Почему отрицательная `rune` не выглядит как нормальный символ

Потому что не каждое значение `int32` - это допустимый Unicode-символ.

### Почему `defer` иногда печатает "не то число"

Потому что замыкание может захватывать саму переменную, а не ее копию.

### Выполняются ли `defer` в обратном порядке

Да.
Последний отложенный вызов выполняется первым.

### Что такое `iota`

Это встроенный счетчик в блоке `const`.

### Почему `fmt.Scan` просит адрес переменной

Потому что функция должна записать данные в твою переменную.

### Что будет с памятью после выхода из функции

Если значение больше нигде не нужно, память потом будет освобождена сборщиком мусора.

### Чем ошибка отличается от паники

Ошибка - обычная ожидаемая ситуация, которую нужно обработать.
Паника - аварийная ситуация, которая ломает поток выполнения.

### Где реально нужны побитовые операции

- флаги;
- права доступа;
- маски;
- низкоуровневый код;
- некоторые оптимизации.

### Почему `string(i)` не переводит число в его текстовый вид

Потому что это интерпретация числа как Unicode-кода символа.
Для числа в строку нужен `strconv.Itoa`.
